### Critical Concepts Documented

#### Authorization is RLS-Based
- ❌ API routes do NOT check permissions
- ✅ Postgres RLS policies enforce all authorization
- Error code 42501 (RLS deny) → API returns 403 Forbidden
- See: API_COURSE_MANAGEMENT.md "Authorization Model"

#### Embedding Generation is Async
- Course created → Trigger fires → Edge Function called (non-blocking)
- Job tracked in `embedding_jobs` table
- 3 retries with exponential backoff if failure
- Search works even during re-embedding (uses old embedding)
- See: EMBEDDINGS_SYSTEM.md "Architecture"

#### Search Degrades Gracefully
- Primary: Vector similarity search (fast, semantic)
- Fallback: Text search (LIKE, slower, keyword-based)
- Only published courses returned
- See: EMBEDDINGS_SYSTEM.md "Search Flow"

#### SEO Uses Absolute URLs
- JSON-LD requires absolute URLs (not relative)
- Set `NEXT_PUBLIC_APP_URL` in env (e.g., https://example.com)
- Image URLs in JSON-LD: `${NEXT_PUBLIC_APP_URL}${relativeUrl}`
- See: SEO_ACCESSIBILITY.md "Environment Variables for SEO"

## Consistency Across Documentation

### Terminology
- **Embeddings**: Vector representations of course text (384-dim gte-small model)
- **Vector search**: Similarity-based search using embeddings
- **Text search**: Keyword-based search using LIKE
- **Semantic search**: Search based on meaning (vector search)
- **RLS**: Row-Level Security (Postgres feature enforcing authorization)
- **SR-only**: Screen reader-only content (visible to assistive tech, not sighted users)
