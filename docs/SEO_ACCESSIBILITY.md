# SEO & Accessibility Improvements

## Overview

The course detail page (`src/app/courses/[id]/page.tsx`) has been enhanced with semantic HTML, structured data (JSON-LD), accessibility landmarks, and metadata generation for better SEO and screen reader support.

**Key improvements:**
- JSON-LD structured data for search engines (Course schema with ratings/offers)
- Semantic HTML: breadcrumb navigation, section landmarks, ordered lists
- ARIA labels and SR-only content for screen readers
- Metadata generation (title, description for Open Graph)
- Proper image alt text for discoverability and accessibility

## Structured Data (JSON-LD)

### Course Schema

```json
{
  "@context": "https://schema.org",
  "@type": "Course",
  "name": "Course Title",
  "description": "Course description",
  "image": "https://example.com/course-image.jpg",
  "provider": {
    "@type": "Organization",
    "name": "EdTech"
  },
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": 4.5,
    "reviewCount": 12
  },
  "offers": {
    "@type": "Offer",
    "price": 49.99,
    "priceCurrency": "USD",
    "availability": "https://schema.org/InStock"
  }
}
```

**Generated by:** `generateMetadata()` on server component + inline `<script type="application/ld+json">`

**Used by:** Google Search (rich snippets), schema.org validators, knowledge graphs

**Fields:**
- `name`: Course title
- `description`: Course description
- `image`: Course banner image (absolute URL)
- `provider.name`: Always "EdTech" (organization name)
- `aggregateRating`: Only included if course has reviews
  - `ratingValue`: Average of all review ratings (0-5)
  - `reviewCount`: Total number of reviews
- `offers.price`: Course price (0 for free)
- `offers.priceCurrency`: Always "USD"
- `offers.availability`: Always "InStock" (courses are always available for purchase)

### Implementation

```tsx
const jsonLd = {
  '@context': 'https://schema.org',
  '@type': 'Course',
  name: course.titulo,
  description: course.descripcion ?? '',
  image: `${appUrl}${courseImageSrc}`,  // Full URL required for JSON-LD
  provider: { '@type': 'Organization', name: 'EdTech' },
  ...(avgRating && {
    aggregateRating: {
      '@type': 'AggregateRating',
      ratingValue: avgRating,
      reviewCount,
    },
  }),
  offers: {
    '@type': 'Offer',
    price: course.precio ?? 0,
    priceCurrency: 'USD',
    availability: 'https://schema.org/InStock',
  },
};

return (
  <>
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
    />
    {/* ... page content ... */}
  </>
);
```

**Notes:**
- JSON-LD is placed in `<head>` via `dangerouslySetInnerHTML`
- Image URL must be absolute (requires `NEXT_PUBLIC_APP_URL` env var)
- Conditional rating: only included if course has reviews

## Metadata Generation

### Page Title & Description

```typescript
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;
  const supabase = await createClient();
  const { data: course } = await supabase
    .from('courses')
    .select('titulo, descripcion, categories(nome)')
    .eq('id', id)
    .maybeSingle();

  if (!course) return { title: 'Curso no encontrado | EdTech' };

  const category = (course.categories as any)?.nome ?? '';
  return {
    title: `${course.titulo} | EdTech`,
    description: course.descripcion
      ? course.descripcion.slice(0, 155)
      : `Aprende ${course.titulo}${category ? ` en la categoría ${category}` : ''} con instructores verificados en EdTech.`,
  };
}
```

**Used by:**
- Browser tab title
- Open Graph (Social media shares)
- Search engine snippets

**Constraints:**
- Title: ~50-60 chars optimal (Google cuts off after ~60 chars on desktop, ~35 on mobile)
- Description: 150-160 chars optimal (Google shows 155-160 chars)

**Current implementation:**
- Title: `Course Title | EdTech` (clear branding)
- Description: First 155 chars of course description, OR auto-generated fallback if no description

### Open Graph & Twitter Cards

Next.js `generateMetadata()` automatically generates:
- `og:title`, `og:description`, `og:type` from returned Metadata object
- `twitter:card`, `twitter:title`, `twitter:description` (derived from OG)

No manual `<meta>` tags needed in JSX.

## Semantic HTML

### Breadcrumb Navigation

```tsx
<nav aria-label="Ruta de navegación">
  <a href="/" style={{ color: '#6b7280', fontSize: '0.875rem' }}>
    ← Volver al catálogo de cursos
  </a>
</nav>
```

**Purpose:**
- Helps users navigate back to course listing
- `<nav>` semantic element indicates navigation (landmark)
- `aria-label` clarifies the breadcrumb's purpose for screen readers

**SEO impact:** Breadcrumbs help search engines understand site structure.

### Section Landmarks

#### Lessons Section

```tsx
<section aria-labelledby="lessons-heading">
  <h2 id="lessons-heading" style={{ ... }}>
    Contenido del curso
  </h2>

  <ol
    className="card"
    aria-label="Lista de lecciones del curso"
  >
    {lessons.map((l, i) => (
      <li key={l.id}>
        <span style={{ ... }} aria-hidden="true">
          {i + 1}
        </span>
        {/* ... lesson content ... */}
      </li>
    ))}
  </ol>
</section>
```

**Semantic elements:**
- `<section>`: Groups related content (lessons)
- `aria-labelledby="lessons-heading"`: Links section to its heading (accessible name)
- `<ol>`: Ordered list (semantic; not just visual ordering)
- `aria-label` on list: Additional context for screen readers
- `aria-hidden="true"` on number: Hides visual ordinal from screen readers (already in list semantics)

#### Reviews Section

```tsx
<section aria-labelledby="reviews-heading" style={{ marginTop: 28 }}>
  <h2 id="reviews-heading" style={{ ... }}>
    Reseñas
  </h2>
  {/* ... review content ... */}
</section>
```

**Same pattern:** `<section>` + `aria-labelledby` for accessible naming.

### Ordered List for Lessons

```tsx
<ol style={{ ... }}>
  {lessons.map((l, i) => (
    <li key={l.id}>
      <span aria-hidden="true">{i + 1}</span>
      {enrolled ? (
        <a href={`/lessons/${l.id}`}>{l.titulo}</a>
      ) : (
        <span>{l.titulo}</span>
      )}
    </li>
  ))}
</ol>
```

**Why `<ol>` instead of `<ul>`?**
- Lessons have a defined order (position field)
- Semantic meaning: order matters (not just a list)
- Screen readers announce "1 of N", "2 of N", etc.

**Notes:**
- Visual ordinal (number) is marked `aria-hidden="true"` because `<ol>` already provides numbering
- Lesson links only shown to enrolled students (access control)

## Accessibility Features

### Alt Text on Images

```tsx
<Image
  src={courseImageSrc}
  alt={`Imagen representativa del curso: ${course.titulo}`}
  width={800}
  height={400}
  style={{ width: '100%', height: 'auto', objectFit: 'cover' }}
  priority
/>
```

**Benefits:**
- Screen readers describe image content to blind users
- SEO: image alt text helps search engines index course content
- Fallback if image fails to load

**Current pattern:**
- `alt={`Imagen representativa del curso: ${course.titulo}`}`
- Clear, descriptive (not just "course image")
- Includes course title for context

### Screen Reader Only Content

#### Star Rating

```tsx
{avgRating && (
  <p style={{ marginBottom: 24 }}>
    <span className="stars" aria-hidden="true">
      {'★'.repeat(Math.round(Number(avgRating)))}
      {'☆'.repeat(5 - Math.round(Number(avgRating)))}
    </span>
    <span className="sr-only">
      Calificación promedio: {avgRating} de 5 estrellas
    </span>
    <span style={{ ... }} aria-hidden="true">
      {avgRating} ({reviewCount} reseña{...})
    </span>
  </p>
)}
```

**Structure:**
- Visual stars: `★★★★☆` (emoji; marked `aria-hidden`)
- SR-only text: "Calificación promedio: 4.5 de 5 estrellas" (accessible to screen readers only)
- Numeric display: `4.5 (12 reseñas)` (aria-hidden; redundant with SR text)

**Why?** Emojis don't convey accurate meaning to screen readers. SR-only text provides the precise meaning.

#### Lesson Lock Icon

```tsx
{enrolled ? (
  <a href={`/lessons/${l.id}`}>{l.titulo}</a>
) : (
  <>
    <span style={{ ... }}>{l.titulo}</span>
    <span style={{ ... }} aria-hidden="true">
      🔒
    </span>
    <span className="sr-only">
      (disponible al inscribirse)
    </span>
  </>
)}
```

**Pattern:**
- Visual lock icon: `🔒` (marked `aria-hidden`)
- SR-only text: "(disponible al inscribirse)" (explains lock to screen reader users)

**Why?** Visual icons don't communicate meaning to screen readers.

### ARIA Labels

```tsx
<p
  style={{ ... }}
  aria-label={`Categoría: ${categoryName}`}
>
  {categoryName}
</p>
```

**Use:** When visual presentation alone is unclear, add ARIA labels to clarify meaning.

**Current issues:**
- Review cards may need labels (currently not labeled with reviewer name, date)
- Enrollment button state (enrolled / not enrolled) needs ARIA feedback

## Image Strategy

### getCourseImage() Utility

```typescript
import { getCourseImage } from '@/lib/courseImages';

const courseImageSrc = getCourseImage(course.titulo, categorySlug);
```

**Returns:**
- URL to a placeholder or real course image
- Falls back to generic category image if no specific image exists
- Used in:
  - Course detail page (banner)
  - SearchCourses component (course card)
  - Course listings (if they exist)

**Note:** Image URLs are relative (e.g., `/images/courses/python.jpg`). JSON-LD requires absolute URLs (prefixed with `NEXT_PUBLIC_APP_URL`).

## Environment Variables for SEO

### NEXT_PUBLIC_APP_URL

**Purpose:** Base URL for absolute image URLs in JSON-LD and Open Graph

**Example values:**
- Development: `http://localhost:3000`
- Production: `https://edtech.example.com`

**Usage:**
```typescript
const appUrl = process.env.NEXT_PUBLIC_APP_URL ?? '';
const jsonLd = {
  image: `${appUrl}${courseImageSrc}`,  // Absolute URL required
};
```

**If not set:** JSON-LD image field is relative (breaks schema validation).

## Common Accessibility Issues & Fixes

### Issue: Similarity score badge not accessible in SearchCourses

**Current code:**
```tsx
{course.similarity !== undefined && (
  <span style={{ ... }}>
    {(course.similarity * 100).toFixed(0)}% relevancia
  </span>
)}
```

**Problem:** Screen readers may skip this or announce "relevance" without context.

**Fix:**
```tsx
{course.similarity !== undefined && (
  <span style={{ ... }} aria-label={`Relevancia: ${(course.similarity * 100).toFixed(0)}%`}>
    {(course.similarity * 100).toFixed(0)}% relevancia
  </span>
)}
```

### Issue: Missing aria-label on review rating

**Current:** Reviews show star ratings but no SR text

**Fix:** Add SR-only text similar to course detail page:
```tsx
<span className="sr-only">
  Calificación: {review.rating} de 5 estrellas
</span>
<span aria-hidden="true">
  {'★'.repeat(review.rating)}{'☆'.repeat(5 - review.rating)}
</span>
```

## Testing Accessibility

### Tools

- **Lighthouse:** Run in Chrome DevTools (Accessibility tab)
- **WAVE:** Browser extension (WebAIM accessibility checker)
- **axe DevTools:** Browser extension (comprehensive audits)
- **Screen reader testing:** NVDA (Windows), JAWS (Windows), VoiceOver (macOS/iOS)

### Manual Tests

1. **Keyboard navigation:** Tab through entire page, verify all buttons/links are reachable
2. **Color contrast:** Check that text meets WCAG AA standards (4.5:1 for normal text, 3:1 for large text)
3. **Screen reader:** Use NVDA (Windows) or VoiceOver (macOS) to navigate course page
4. **Search functionality:** Test SearchCourses with keyboard only (no mouse)

### Example Test Scenario

1. Open page in screen reader (NVDA)
2. Navigate through page structure:
   - Breadcrumb nav announces "Ruta de navegación"
   - Course title announces as heading level 1
   - Sections announce as landmarks with labels
   - Lesson list announces as ordered list with count
3. Verify all interactive elements (buttons, links) are reachable
4. Verify images have alt text
5. Verify no missing labels or ARIA attributes
